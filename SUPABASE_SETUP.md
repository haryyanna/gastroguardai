# Supabase Setup for Cross-Device Sync

Jika data check-in dari device lain tidak muncul di admin, biasanya penyebabnya:

1. Frontend belum pakai kredensial Supabase (`VITE_SUPABASE_URL` dan `VITE_SUPABASE_ANON_KEY` kosong).
2. Tabel/policy RLS belum mengizinkan `anon` untuk `select/insert`.

## Penting untuk Uji Lapangan

Gunakan **satu project Supabase yang sama** untuk semua device (URL + anon key sama persis).  
Dashboard admin membaca data cloud dari tabel `users/user` + `checkins`.

## 0) Aktifkan Supabase Auth (Email/Password)

1. Buka `Authentication -> Providers`.
2. Aktifkan provider `Email`.
3. Nonaktifkan `Confirm email` jika ingin login langsung setelah register (opsional untuk demo).

## 0.1) (Opsional) Tabel Analytics Event

Jika ingin event analytics tersimpan di Supabase, jalankan SQL berikut:

```sql
create table if not exists public.analytics_events (
  id bigint generated by default as identity primary key,
  event_name text not null,
  username text,
  payload jsonb not null default '{}'::jsonb,
  occurred_at timestamptz not null default now()
);

alter table public.analytics_events enable row level security;

drop policy if exists "analytics_insert_anon" on public.analytics_events;
create policy "analytics_insert_anon"
on public.analytics_events
for insert
to anon
with check (true);
```

## 1) Isi `.env`

Duplikat `.env.example` menjadi `.env`, lalu isi:

```env
VITE_SUPABASE_URL=https://YOUR_PROJECT_REF.supabase.co
VITE_SUPABASE_ANON_KEY=YOUR_SUPABASE_ANON_KEY
```

Restart server Vite setelah ubah `.env`.

### Logika otomatis seri device

Aplikasi akan mendeteksi perangkat dari `navigator.userAgent`, lalu menghasilkan label seperti:

- `OPPO CPH2237`
- `Xiaomi Redmi Note 12`
- `Apple iPhone`
- `Samsung Galaxy`

Lalu data disimpan ke tabel `devices` dan `family_locations` dengan kolom:

- `device_id`
- `brand`
- `model`
- `series`
- `device_name`
- `last_seen_at`
- `updated_at`

Jadi orang tua bisa memilih device berdasarkan seri asli HP, bukan hanya `Anak 1` dan `Anak 2`.

## 3) Verifikasi cepat

1. Buka app dari device A, simpan check-in.
2. Buka app dari device B, simpan check-in lain.
3. Buka halaman admin:
   - Jika terkoneksi Supabase, header akan menunjukkan `(Cloud)`.
   - Jika fallback lokal, header akan menunjukkan `(Local)` dan muncul warning.

## 4) Hardening Wajib (Sebelum Uji Lapangan)

Jalankan SQL ini agar identitas user konsisten lintas device dan check-in tidak duplikat per hari:

```sql
alter table if exists public.users
  add column if not exists auth_uid uuid unique;

alter table if exists public."user"
  add column if not exists auth_uid uuid unique;

alter table if exists public.checkins
  add column if not exists checkin_day date generated always as ((timezone('Asia/Makassar', created_at))::date) stored;

create unique index if not exists ux_checkins_user_day
on public.checkins(user_id, checkin_day);
```

Jika pakai Supabase Auth login (email/password), pastikan policy `users/user` dan `checkins` juga mengizinkan role `authenticated` selain `anon` (atau gunakan `to public`).

## 5) SQL Komunitas Lintas Device (wajib jika fitur komunitas dipakai)

Jalankan SQL ini agar posting komunitas terbaca di semua device dan nama pengirim mengikuti akun aktif:

```sql
create extension if not exists pgcrypto;

create table if not exists public.community_posts (
  id uuid primary key default gen_random_uuid(),
  content text not null check (char_length(content) <= 280),
  author_name text not null,
  likes integer not null default 0 check (likes >= 0),
  created_at timestamptz not null default now()
);

alter table public.community_posts enable row level security;

drop policy if exists "community_select_public" on public.community_posts;
drop policy if exists "community_insert_public" on public.community_posts;
drop policy if exists "community_update_public" on public.community_posts;
drop policy if exists "community_delete_public" on public.community_posts;

create policy "community_select_public"
on public.community_posts
for select
to public
using (true);

create policy "community_insert_public"
on public.community_posts
for insert
to public
with check (char_length(author_name) > 0 and char_length(content) > 0);

create policy "community_update_public"
on public.community_posts
for update
to public
using (true)
with check (char_length(author_name) > 0 and char_length(content) > 0);

create policy "community_delete_public"
on public.community_posts
for delete
to public
using (true);

create index if not exists idx_community_posts_created_at
on public.community_posts(created_at desc);
```

## 6) Verifikasi Akhir (sebelum publish)

1. Login user A, check-in, lalu refresh admin.
2. Login user B dari device lain, check-in, lalu refresh admin.
3. Buat posting komunitas dari user A, cek muncul di user B.
4. Hapus 1 posting dari user A, cek feed user B ikut ter-update.
5. Pastikan status sinkronisasi di komunitas menunjukkan `Cloud aktif (lintas device)`.
